Clash 代理组配置完整指南

代理组是 Clash 的核心功能之一。它把多个节点组织起来,实现手动切换、自动选择、故障切换、负载均衡等功能。理解代理组的工作原理和配置方法,你就能根据需求灵活组合节点,打造最适合自己的分流策略。

什么是代理组

简单说,代理组就是一组节点的集合。规则中不直接指定节点,而是指定代理组,由代理组决定实际用哪个节点。

例子:

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - 香港节点1
      - 香港节点2
      - 美国节点1

rules:
  - DOMAIN-SUFFIX,google.com,Proxy  # 访问 Google 时用 Proxy 组

这样配置后,访问 Google 时会使用 Proxy 组中当前选中的节点。如果节点挂了,你可以在 Proxy 组中切换到其他节点,不用改规则。

四种代理组类型

select - 手动选择

最常用 灵活

工作方式:你手动选择用哪个节点,不会自动切换。

配置示例:

proxy-groups:
  - name: "Proxy"
    type: select
    proxies:
      - 香港节点1
      - 香港节点2
      - 美国节点1
      - DIRECT  # 也可以包含 DIRECT（直连）

适用场景:

  • 你想自己控制用哪个节点
  • 不同网站需要不同地区的节点（如 Netflix 美区、日区）
  • 测试不同节点的速度

优点:

  • 完全可控
  • 可以包含其他代理组作为选项
  • 可以随时切换

缺点:

  • 节点挂了不会自动切换
  • 需要手动选择

url-test - 自动测速

智能 自动

工作方式:定期测试所有节点延迟,自动选择延迟最低的节点。

配置示例:

proxy-groups:
  - name: "Auto"
    type: url-test
    proxies:
      - 香港节点1
      - 香港节点2
      - 新加坡节点1
    url: 'http://www.gstatic.com/generate_204'
    interval: 300
    tolerance: 50

参数说明:

  • url - 测速用的网址,通常用 gstatic（Google 的测速服务）
  • interval - 测速间隔（秒）,这里是 300 秒 = 5 分钟
  • tolerance - 容差（毫秒）,只有新节点比当前节点快 50ms 以上才切换

适用场景:

  • 你有多个相似的节点（如多个香港节点）
  • 想自动选择最快的节点
  • 不想手动切换节点

优点:

  • 自动选择最快节点
  • 节点慢了会自动切换
  • 省心

缺点:

  • 无法手动控制用哪个节点
  • 测速有流量消耗
  • 可能频繁切换节点（如果设置不当）
优化建议:tolerance 不要设太小,否则会频繁切换。一般设 50-150ms。interval 不要太短,5-10 分钟就够了。

fallback - 故障切换

可靠 自动

工作方式:按顺序优先使用第一个节点,如果第一个节点挂了,自动切换到第二个。

配置示例:

proxy-groups:
  - name: "Fallback"
    type: fallback
    proxies:
      - 主力节点
      - 备用节点1
      - 备用节点2
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

工作流程:

  1. 默认使用"主力节点"
  2. 每 300 秒测试一次主力节点
  3. 如果主力节点超时,切换到"备用节点1"
  4. 主力节点恢复后,会切回主力节点

适用场景:

  • 你有一个主力节点,速度快但不太稳定
  • 想要故障自动切换
  • 追求可靠性

优点:

  • 自动故障切换
  • 优先使用最好的节点
  • 节点恢复后自动切回

缺点:

  • 不会自动选最快的,只用第一个可用的
  • 节点顺序很重要

load-balance - 负载均衡

高级 分散

工作方式:把流量分散到多个节点,每个连接随机选择一个节点。

配置示例:

proxy-groups:
  - name: "LoadBalance"
    type: load-balance
    proxies:
      - 节点1
      - 节点2
      - 节点3
    url: 'http://www.gstatic.com/generate_204'
    interval: 300
    strategy: consistent-hashing

strategy 策略:

  • consistent-hashing - 一致性哈希,同一个域名总是用同一个节点
  • round-robin - 轮询,每个连接依次使用不同节点

适用场景:

  • 多个节点带宽都不够大,需要分散流量
  • 下载大文件,想同时用多个节点的带宽
  • 高级用户优化

优点:

  • 充分利用多个节点的带宽
  • 单个节点压力小

缺点:

  • 配置复杂
  • 某些网站可能检测到多 IP 访问
  • 延迟可能不稳定
建议:除非你真的需要分散流量,否则不推荐用 load-balance。大部分情况 select 或 url-test 就够了。

代理组嵌套

代理组可以包含其他代理组,实现更灵活的策略。

示例:分地区选择

proxy-groups:
  # 顶层选择组
  - name: "Proxy"
    type: select
    proxies:
      - Auto-HK
      - Auto-US
      - Auto-SG
      - DIRECT

  # 香港自动组
  - name: "Auto-HK"
    type: url-test
    proxies:
      - 香港节点1
      - 香港节点2
      - 香港节点3
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

  # 美国自动组
  - name: "Auto-US"
    type: url-test
    proxies:
      - 美国节点1
      - 美国节点2
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

  # 新加坡自动组
  - name: "Auto-SG"
    type: url-test
    proxies:
      - 新加坡节点1
      - 新加坡节点2
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

这样配置后:

  • 在 Proxy 组中可以选择用香港、美国还是新加坡
  • 每个地区内部自动选择最快的节点
  • 兼顾了灵活性和自动化

实用配置案例

案例 1:日常使用配置

proxy-groups:
  # 主代理组 - 手动选择用哪个策略
  - name: "Proxy"
    type: select
    proxies:
      - Auto  # 自动选最快
      - 香港
      - 美国
      - DIRECT

  # 自动选择组 - 从所有节点中选最快的
  - name: "Auto"
    type: url-test
    proxies:
      - 香港节点1
      - 香港节点2
      - 美国节点1
      - 新加坡节点1
    url: 'http://www.gstatic.com/generate_204'
    interval: 300
    tolerance: 100

  # 手动香港组
  - name: "香港"
    type: select
    proxies:
      - 香港节点1
      - 香港节点2

  # 手动美国组
  - name: "美国"
    type: select
    proxies:
      - 美国节点1
      - 美国节点2

案例 2:流媒体分流配置

proxy-groups:
  # 通用代理
  - name: "Proxy"
    type: select
    proxies:
      - Auto
      - DIRECT

  # 自动选择
  - name: "Auto"
    type: url-test
    proxies:
      - 香港节点1
      - 香港节点2
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

  # Netflix 专用（需要美国原生 IP）
  - name: "Netflix"
    type: select
    proxies:
      - 美国原生IP节点
      - 新加坡节点

  # YouTube 专用（香港速度快）
  - name: "YouTube"
    type: select
    proxies:
      - 香港节点1
      - 香港节点2
      - 台湾节点

rules:
  - DOMAIN-SUFFIX,netflix.com,Netflix
  - DOMAIN-SUFFIX,youtube.com,YouTube
  - MATCH,Proxy

案例 3:故障切换 + 手动选择

proxy-groups:
  # 手动选地区
  - name: "Proxy"
    type: select
    proxies:
      - Fallback-HK
      - Fallback-US
      - DIRECT

  # 香港故障切换
  - name: "Fallback-HK"
    type: fallback
    proxies:
      - 香港高速节点
      - 香港备用节点1
      - 香港备用节点2
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

  # 美国故障切换
  - name: "Fallback-US"
    type: fallback
    proxies:
      - 美国高速节点
      - 美国备用节点
    url: 'http://www.gstatic.com/generate_204'
    interval: 300

常见问题

Q: url-test 组一直在切换节点怎么办?

增大 tolerance 参数。比如从 50 改成 150,这样只有新节点明显更快时才切换。
Q: 可以在代理组中引用节点正则吗?

可以。使用 use 参数引用 provider,或用 filter 过滤节点名称。但这是 Clash Premium 的功能,普通版本不支持。
Q: 代理组的顺序重要吗?

对 select 和 fallback 很重要。select 组中第一个选项是默认选中的;fallback 组优先使用第一个节点。对 url-test 和 load-balance 不重要。
Q: 测速 URL 用什么好?

推荐用 http://www.gstatic.com/generate_204（Google）或 http://cp.cloudflare.com/generate_204（Cloudflare）。响应快且稳定。

总结

选择代理组类型的建议:

  • 日常使用: select + url-test 嵌套
  • 追求稳定: select + fallback 嵌套
  • 完全自动: url-test
  • 完全手动: select
  • 特殊需求: load-balance（不推荐新手）

代理组配置没有绝对的"最优解",关键是理解每种类型的特点,根据自己的需求组合使用。先从简单的 select 开始,熟悉后再尝试 url-test 和嵌套配置。
